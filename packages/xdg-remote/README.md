# xdg-remote

A two-part utility to shim `xdg-open` on remote Linux systems (like devservers or containers) and pass requested URLs back to a local receiver (your desktop) for opening.

## Intent

When working in remote environments (SSH, Docker, etc.), tools often try to open browser windows using `xdg-open`. On a headless system, this usually fails. `xdg-remote` solves this by:
1. Providing a **Receiver** that runs on your local desktop.
2. Providing a **Shim** that replaces `xdg-open` on the remote system.
3. Securely passing the URL from the remote system to the local one via a simple HTTP-based protocol.

## Architecture

### xdg-receiver
- **Role**: Runs on the machine where you want the browser to open (e.g., your laptop).
- **First Run**: 
  - Asks for FQDN/IP and a port.
  - Generates a 16-byte secure hex key.
  - Generates a Base64-encoded **Connection String** containing these details.
  - Stores configuration in `~/.local/state/ruinous-xdg-receiver/connection-string`.
- **Operation**: Starts a lightweight Python HTTP server that listens for authenticated POST requests containing URLs.

### xdg-shim
- **Role**: Runs on the remote machine where you are working.
- **Setup**: 
  - Run `xdg-remote-shim` and paste the connection string generated by the receiver.
  - Stores the string in `~/.local/state/ruinous-xdg-shim/connection-string`.
- **xdg-open**:
  - A replacement script that reads the connection string.
  - Sends URLs to the receiver using `curl`.

## Usage

### 1. On your Local Desktop
Run the receiver:
```bash
nix run .#xdg-remote -- xdg-remote-receiver
```
Copy the generated connection string.

### 2. On the Remote System
Configure the shim:
```bash
# Ensure xdg-remote is in your path
xdg-remote-shim
```
Paste the connection string when prompted.

Now, any tool that calls `xdg-open` will send the URL to your desktop receiver.

## Security
- Authentication is handled via a pre-shared key (PSK) included in the connection string.
- The receiver only accepts POST requests with the correct key.
- Note: Traffic is currently unencrypted HTTP. It is recommended to use this over a secure network or via an SSH tunnel/Tailscale.
